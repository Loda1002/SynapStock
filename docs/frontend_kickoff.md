# 402 Guard 프론트엔드 — 작업 시작 브리프 (프론트 개발자용)

> **이 파일을 데스크탑 Claude Code 에 그대로 붙여넣고 시작하세요.** 백엔드와 분리해 작업하고
> 나중에 충돌 없이 병합하기 위한 규칙·계약·시안 스펙·작업 순서가 전부 여기 있습니다.
> 먼저 반드시 함께 읽을 문서: **[docs/frontend_backend_split.md](frontend_backend_split.md)** (경계·상태 스키마 계약·병합 절차).

## 0. 당신의 역할과 경계 (가장 중요)

- **당신은 `web/static/**` 만 편집합니다.** `index.html`·`login.html`·`css/theme.css`·`css/skeleton.css`·`js/app.js` + 새로 만들 `landing.html`.
- **`.py` 파일·`server.py`·엔진·설정은 절대 건드리지 않습니다.** 그건 백엔드(다른 작업자) 소유입니다. 새 라우트나 새 상태 필드가 필요하면 코드로 만들지 말고 백엔드에 요청하세요.
- 이 경계를 지키면 두 사람의 변경 파일이 겹치지 않아 **git 병합 충돌이 0** 입니다.

## 1. 셋업 — 백엔드 없이도 UI 를 실제 데이터로 개발할 수 있습니다

```bash
git clone <repo> && cd solana-agent
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt   # Windows PowerShell
.venv\Scripts\python -m web.server              # http://127.0.0.1:8000
```

- 브라우저에서 열고 **"세션 시작(dry)"** 를 누르면 시세가 흐르고 `guard`·`per_symbol` 등 실제 상태가 채워집니다.
- **dry(모의) 모드는 지갑 비밀키가 필요 없습니다** — 엔진이 모의 지갑을 만들고, `GEMINI_API_KEY` 가 없으면 규칙 폴백으로 돕니다. **당신은 비밀키·`.env` 없이** UI 를 개발할 수 있습니다.
- **랜딩 페이지**는 서버 없이 `web/static/landing.html` 을 브라우저로 직접 열거나 `http://127.0.0.1:8000/static/landing.html` 로 열어 개발합니다.
- 포트가 겹치면(`Port … in use`) 데스크탑 Claude Code `.claude/launch.json` 에서 `autoPort: true`.

## 2. 디자인 시안

- **위치**: `docs/design/dashboard_mockup.png` (저장소에 커밋돼 있습니다 — Read 로 열어 보세요).
- 이 시안은 **대시보드 페이지의 디자인**입니다. **배치·간격·색·컴포넌트 형태의 기준**으로 씁니다.
- ⚠ 시안은 **프로토타입**이라 실제보다 단순합니다. 특히 **① 멀티 종목 UI(종목 체크박스·포커스 드롭다운·종목별 요약표)와 ② 가드 KPI 카드가 시안에 없습니다.** → 시안을 통째로 새로 짜지 말고, **이미 동작하는 마크업을 유지한 채 시안의 룩을 입히고, 빠진 요소는 추가**하세요(§4·§5).

## 3. ⚠ 가장 중요 — 메시징 재조정 (시안의 카피는 바꿔서 씁니다)

시안은 **"Auto Trader — 돈을 넣어두면 AI가 알아서 사고 팝니다"** 라는 옛 트레이딩 봇 카피로 돼 있습니다. 그런데 이 제품의 **핵심 포지셔닝은 "402 Guard — 사람 없이 결제하는 AI 에이전트의 지출을 지키는 승인 게이트"** 입니다(근거·상세: [docs/differentiation.md](differentiation.md)). 심사에서 "흔한 매매 봇"으로 분류되면 탈락 위험이 크다는 게 자체 심사 리포트의 결론입니다([docs/reports/judging_latest.md](reports/judging_latest.md)).

**따라서 시안의 레이아웃·색·컴포넌트는 그대로 쓰되, 브랜딩과 카피는 아래 표대로 바꾸고, 가드 KPI 카드를 첫 화면 최상단에 새로 넣습니다.**

| 위치 | 시안(옛) | → 402 Guard(신) |
|---|---|---|
| 헤더 브랜드·`<title>` | Auto Trader | **402 Guard** |
| 히어로/태그라인 | 한도 안에서 스스로 사고파는 AI 에이전트 | **사는 쪽 에이전트를 지키는 지출 승인 게이트** |
| 첫 화면 강조 | 수익률·총자산 | **가드 KPI(시도·차단·유출 0.00·오탐 0)** — 새 카드 |
| ABOUT 헤드라인 | 돈을 넣어두면, AI가 알아서 사고 팝니다 | **한도를 정하면, 에이전트는 그 안에서만 씁니다** |
| ABOUT 3포인트 | 1 한도를 정합니다 / 2 AI가 시세를 판단합니다 / 3 근거를 그대로 보여줍니다 | **1 한도를 정합니다 / 2 에이전트가 그 한도 안에서만 지출합니다 / 3 악성 청구는 차단하고, 유출은 0으로 증명합니다** |

> 트레이딩 결과(오늘의 결과·손익·차트·타임라인)는 **그대로 유지**합니다 — 없애는 게 아니라, 그 위에 "이 모든 지출이 한도 안에서·유출 0 으로 일어났다"는 가드 서사를 **얹는** 것입니다.

## 4. 시안 구조 분해 → 기존 카드 매핑

현재 대시보드는 **12개의 `data-card` 모듈**로 돼 있고(`web/static/index.html`), 순서는 `app.js` 의 `DEFAULT_LAYOUT` 배열 하나로 정해집니다(카드 제목을 끌어 재배치·localStorage 저장). **시안은 이 모듈들을 시각적으로 묶은 모습**입니다 — 모듈을 부수지 말고 CSS/레이아웃으로 그룹처럼 보이게 하세요.

| 시안 섹션 | 구성(시안) | 기존 `data-card` 모듈 |
|---|---|---|
| **(신규) 가드 KPI** | 시도·차단·한도거부·**유출 0.00 USDC** | **없음 → 새로 추가** (`data-card="guard"`) |
| **오늘의 결과** | 자연어 요약 문장 + 총자산·손익(실현)·평가손익(미실현)·포지션 4타일 | `pnl` + `valuation` + `position` (+ `budget` 일부) 를 한 섹션처럼 |
| **AI 판단 근거** | 캔들차트(TAAPL/USDC·MA·양봉/음봉) + AI 판단 타임라인(HOLD/BUY/SELL 색점) | `price`(차트) + `decisions`(타임라인) 나란히 |
| **거래 내역** | 거래표(시각·방향·수량·단가·수수료·총액) + 협상 이벤트 로그 | `trades`(표) + `log`(협상 로그) 나란히 |
| **한도 설정 / 데일리 브리핑** | 총예산·건별최대·허용종목·AP2 사용/잔여·수수료 + 브리핑 | `budget` + `mandate` / `briefing` 나란히 |
| **ABOUT** | 헤드라인 + 설명 + 3포인트 | 신규 정적 섹션(대시보드 하단 또는 랜딩으로) |
| (시안에 없음·유지) | — | `symbols`(멀티종목 요약표·단일이면 숨김), `session`(세션 시작/정지·전략·시세 선택 컨트롤) |

- **`session` 카드(세션 시작/정지·전략·속도·종목 선택)는 시안에 안 보이지만 반드시 유지**합니다 — 이게 없으면 데모를 못 돌립니다. 상단 툴바나 접이식 설정 패널로 배치하세요.
- **`symbols` 카드(멀티종목)**: 종목을 여러 개 고른 세션에서만 표시(단일이면 `hidden`). 시안엔 없으니 시안 톤에 맞춰 추가합니다.

### 가드 KPI 카드 스펙 (신규 — 최우선)

- 위치: **`오늘의 결과` 위, 첫 화면 히어로**. `DEFAULT_LAYOUT` 배열 맨 앞에 `"guard"` 추가.
- 4타일: **시도(`attempts`) · 차단(`blocked`) · 한도 거부(`ap2_rejected`) · 유출(`leak_usdc`)**. **유출은 "0.00 USDC" 를 가장 크게·초록으로 강조**(핵심 KPI).
- 데이터: `state.guard.{attempts, blocked, ap2_rejected, leak_usdc}` (이미 백엔드가 방출 중 — [계약 §2.2](frontend_backend_split.md)).
- `app.js`: 상태 갱신(SSE `state`)마다 이 카드도 갱신하는 렌더 함수 추가. `index.html` 에 `<section class="card" data-card="guard">…</section>` 마크업 추가.

## 5. 작업 순서 (우선순위)

1. **가드 KPI 카드 추가** (§4) — 첫 화면에 "유출 0.00 USDC". 백엔드 데이터가 이미 준비돼 배선만 하면 되는 최고효율 작업.
2. **리브랜딩 + 카피 치환** (§3 표) — 헤더·타이틀·ABOUT.
3. **시안 스킨을 대시보드에 적용** — `theme.css` 변수(색·글꼴·간격)를 시안 값으로 교체 + `DEFAULT_LAYOUT` 재배열(guard→오늘의결과→판단근거→거래→한도/브리핑) + 카드 마크업을 시안 그룹 형태로. **기존 멀티종목·세션 컨트롤 기능은 유지.**
4. **랜딩 페이지 `landing.html`** — 스티키 상단바(브랜드+`시작하기`→`/login`) + 히어로(대시보드 스크린샷을 `filter: blur()` 로 흐릿하게, "데모처럼") + 스크롤 시 ABOUT 섹션(시안 ABOUT 재사용, §3 카피). 시안의 상단 나비·ABOUT 컴포넌트를 그대로 재활용.
5. **로그인 + 지갑 등록 `login.html`** — 현재 로그인/회원가입 자리표시 껍데기에 **지갑 등록 단계**를 얹고, 완료 후 `/app`(대시보드)로 이동. 실제 인증 백엔드는 제출 후 로드맵이라 지금은 UI 흐름만.

> 시안 상단 나비의 `포트폴리오·AI 인사이트·리포트·소개` 는 지금 별도 페이지로 만들지 마세요 — **기존 섹션으로 스크롤 이동(앵커)하거나 "출시 예정" 처리**합니다. 새 페이지는 랜딩·로그인·대시보드 3개까지만. `입금하기+` 버튼도 당장은 `/login`(지갑 등록)으로 연결하는 자리표시.

## 6. 계약 — 건드리지 말 것 (병합·기능 보호)

- **상태 스키마([§2.2](frontend_backend_split.md))의 필드 이름은 읽기만** 합니다. 없는 필드가 필요하면 백엔드에 요청(직접 `.py` 수정 금지).
- **기존 기능을 깨지 마세요**: 멀티종목 선택·세션 시작/정지·일시정지·한도 변경·SSE 재연결·판단 출처 범례. 스킨 작업 중 이 동작들이 그대로 되는지 확인.
- 카드 배치 저장 키(`autotrader_layout_v1`)를 바꿨다면(예: guard 를 기본 상단에 강제) **키 버전을 올려**(`_v2`) 기존 사용자 localStorage 가 새 배치를 받게 하세요.
