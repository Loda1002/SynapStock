## 1. 무엇이 바뀌었나 — 기능이 아니라 "이야기"가 바뀌었습니다

제품이 하는 일은 시안 그리실 때와 같습니다.

1. 사용자가 한도를 정한다 (총예산 · 건별 최대 · 허용 종목)
2. AI 에이전트가 시세를 보고 스스로 사고팔기를 판단한다
3. 블록체인(솔라나) 위에서 USDC로 진짜 결제가 일어난다

여기에 **한 겹이 더 붙었고, 그게 이제 제품의 이름이 되었습니다.**

4. **돈이 지갑에서 나가기 직전, 청구서를 검사하는 문지기가 있다.** 이름이 **402 Guard**입니다.

`402`는 인터넷 표준 응답 코드 중 "이 서비스는 유료입니다(HTTP 402 Payment Required)"를 뜻합니다. AI 에이전트가 결제를 요구받는 바로 그 지점이라, 거기 서 있는 문지기라는 뜻입니다.

## 2. 왜 바꿨나 — 디자인 판단에 영향을 주는 근거

이건 취향 문제가 아니라 **심사 결과를 좌우하는 문제**라서 공유드립니다. 어제(07-26~27) 유사 해커톤 12개의 수상작·탈락작을 조사한 결과입니다.

**(가) "AI 트레이딩 봇"으로 읽히면 천장이 낮습니다.**
멀티에이전트 + 구글 클라우드 풀스택 + 실시세 + 배포까지 다 갖춘 트레이딩 프로젝트(TradeSage AI, Vigil AI)가 전부 **장려상급(Honorable Mention)에서 멈췄습니다.** 반대로 같은 대회 대상은 "장바구니로 레시피 추천"이라는 **한 문장짜리 제품**이었습니다.

**(나) 그렇다고 매매를 숨기면 안 됩니다.** ← *이전 브리프에서 한 번 정정된 부분입니다*
자동 운용 제품이 수상한 사례가 최소 3건 확인됐습니다(Peaks, Clawpump, Agent Arc). 정확한 교훈은 "자동매매라서 떨어진다"가 아니라 **"단일 전략 봇의 언어로 말하면 떨어진다"** 입니다. → **화면에서 매매·차트·수익을 지우지 않습니다. 순서만 바꿉니다.**

**(다) "막는다"보다 "그래서 맡길 수 있다"가 이깁니다.** ← *가장 중요한 카피 방향*
같은 대회에서
- 순수 방어 도구(`Cronos Shield`, "안전 보호막") → **2위 $5,000**
- 방화벽·검사기(`x402 Intent Firewall`) → 메인 트랙도 아닌 **개발자 도구 부문 $3,000**
- **1위 $24,000** (`AgentFabric`) → 같은 안전 문제를 *"자율성을 가능케 하는 권한 레이어"* 로 말함

→ **"차단·방어·게이트"만 강조하면 제품이 아니라 라이브러리로 분류됩니다.** 문구는 항상 *"막는다"* 가 아니라 *"막아주니까 비로소 사람 없이 맡길 수 있다"* 로 갑니다.

**(라) 첫 화면에 전문용어를 쌓으면 기술이 아무리 좋아도 0점입니다.**
`GuardianOS`라는 프로젝트는 온체인 승인 게이트 + 실제 배포 + 라이브 URL을 다 갖추고도 **무수상**이었습니다. 화면에 자기들만 아는 용어(`Tenth Opinion Protocol`, `3-of-5 합의`)를 쌓아 놓은 게 유력한 원인으로 보입니다. **심사 시간은 3분이고, 심사위원 전원이 블록체인 전문가가 아닙니다.**

→ **첫 화면 규칙: 한 문장 + 숫자 4개. 그 외 용어(x402·AP2·A2A·mandate)는 전부 아래 접힌 영역으로.**

## 3. 비유 하나 — 회의에서 이걸로 설명하면 가장 빠릅니다

> 회사가 직원에게 **법인카드**를 줍니다. 한도를 100만 원으로 걸어 뒀습니다.
> 그런데 거래처가 **99만 원짜리 청구서**를 보내면서 **입금 계좌만 자기 개인 계좌로 바꿔** 적었습니다.
> **한도는 지켜졌습니다. 그리고 돈은 전액 사라집니다. 물건도 오지 않습니다.**

한도만으로는 부족합니다. 결제 직전에 이걸 확인하는 사람이 필요합니다.

1. **금액** — 우리가 합의한 견적과 청구서 금액이 같은가
2. **받는 사람** — 원래 그 거래처가 맞는가 (등록된 곳 외에는 거부)
3. **물건** — 사기로 한 그 종목이 맞는가
4. **배송** — 돈이 나간 뒤, 물건이 진짜 왔는지 블록체인에서 다시 조회

사람이 없는 24시간 자동 결제에서는 이 확인을 **사람이 할 수 없습니다.** 그래서 코드가 대신합니다. **그게 402 Guard이고, 지금 이 제품의 이름입니다.**

## 5. 새로 그려주셨으면 하는 것 (우선순위 순)

### ① 가드 KPI 행 — 최우선, 첫 화면 최상단

숫자 4개를 한 행으로. **`유출 0.00 USDC`가 가장 크고 눈에 띄어야 합니다.**

```
   시도            차단            한도 거부         유출  0.00 USDC
   (지출 시도 건수)   (게이트가 막음)    (한도 초과 거부)     ← 이게 주인공. 가장 크게
```

- 숫자는 **세션마다 실시간으로 바뀝니다**(고정값 아님). 참고로 자체 공격 테스트를 돌리면 *공격 6건 중 서명 전 4건 차단 · 정상 거래 14건 오탐 0*이 나옵니다.
- 톤: **경고(빨강)가 아니라 안심(초록/성공)** 입니다. "사고가 났다"가 아니라 "아무것도 새지 않았다"는 화면입니다.
- ⚠ **정직성 단서 한 줄이 필요합니다.** 이 `0.00`은 *"서명하기 전에 막은 것"*의 유출이고, 결제가 끝난 뒤에 상대가 물건을 안 보내는 경우는 **탐지·정지만 되고 되돌릴 수 없습니다.** 작은 글씨로라도 이 구분이 화면에 있어야 합니다 — 없으면 심사에서 "그 0.00은 어떻게 잰 숫자냐"는 질문에 무너집니다.
- ⚠ 다만 §2-(다) 때문에 **라벨을 방어 용어로만 채우지 말아 주세요.** 이 행 위나 옆에 *"그래서 사람 없이 맡길 수 있습니다"* 계열의 한 줄이 붙어야 합니다.

### ② "차단되는 순간"의 시각 표현 — 이 제품의 구조적 약점을 화면으로 뒤집는 곳

이 제품의 성과는 **"아무 일도 일어나지 않는 것"** 입니다. 화면상 사건이 없어서 데모가 밋밋해질 위험이 가장 큽니다(조사에서 지적된 주요 리스크).

데모 영상과 심사에서 보여줄 장면은 이렇습니다.

1. 악성 거래처가 **받는 사람 주소를 바꾼 청구서**를 보낸다
2. 402 Guard가 서명 **직전에** 막는다 → 화면에 차단 사유 표시
3. 잔액이 **소수점까지 그대로**임을 보여준다 → `유출 0.00`

→ **2~3번이 "눈에 보이는 사건"이 되도록 시각화가 필요합니다.** (차단 배지 / 흐름 정지 애니메이션 / 잔액 숫자가 안 움직이는 걸 강조하는 표현 등 — 방향은 디자이너님 제안을 듣고 싶은 부분입니다.)

### ③ 랜딩 페이지 (신규 1장)

- 스티키 상단바(브랜드 + `시작하기`)
- 히어로: §6의 2단 구조 문장 + 대시보드 미리보기
- 스크롤: ABOUT 섹션(시안 것 재사용, 카피만 교체)

### ④ 로그인 / 지갑 연결 화면 (신규 1장)

- 이 서비스는 **지갑 연결이 곧 로그인**입니다(아이디·비밀번호 없음).
- 흐름: `지갑 연결` → `한도 정하기(총예산·건별 최대·허용 종목)` → `위임장에 1회 서명` → 대시보드
- **핵심 안심 문구가 화면에 있어야 합니다**: *"개인키를 서버에 보관하지 않습니다. 한도 안에서만, 지정한 상대에게만 지출됩니다. 언제든 즉시 정지할 수 있습니다."*
- ⚠ **"매 거래마다 승인" 버튼은 넣지 않습니다.** 사람이 매번 승인하면 이 제품의 전제(무인 자율 결제)가 무너집니다. 사용자는 **처음에 한 번** 위임장에 서명합니다.

### ⑤ 멀티 종목 UI (시안에 없는 실제 기능)

종목을 여러 개 동시에 굴릴 수 있습니다 → 종목 선택 체크박스 · 포커스 전환 · 종목별 요약표가 필요합니다.

### ⑥ 아키텍처 다이어그램 1장 (제출물 필수 요소)

소개서에 아키텍처가 필수입니다. 4계층이면 충분합니다: **사용자(지갑·한도 서명) → AI 에이전트(판단) → 402 Guard(청구서 검증) → 솔라나(USDC 정산)**.

## 7. 절대 하지 말 것 (한 줄씩)

1. **매 거래 "승인" 버튼** — 무인 자율 결제라는 제품 전제가 무너집니다
2. **수익률을 첫 화면 주인공으로** — "또 하나의 트레이딩 봇"으로 분류됩니다
3. **매매·차트·수익을 화면에서 삭제** — 반대로 이것도 틀립니다. 두 번째 줄로 내릴 뿐입니다
