# 기능 구체화 스펙 (2026-07-23 확정 — 웹 서비스화 대화에서 이 문서 기준으로 구현)

> 선택 배경은 [`docs/feature_candidates.md`](feature_candidates.md) 참고. 구현 순서는 P1 → P2 → P3.
> 공통 원칙: **어떤 기능도 AP2 mandate(한도)를 우회할 수 없다.** 모든 상태 변화는 이벤트 로그에 남긴다.

## 필수군 vs 어필군

| 구분 | 기능 | 데모·소개서 취급 |
|---|---|---|
| 필수(뼈대) | A1 대시보드, A2 긴급정지, A3 한도 설정, A4 알림, A5 거래 내역 | "당연히 있는 기본기"로 짧게 |
| 어필(강조) | A6 판단 타임라인, A7 손익 리포트, A8 수수료 투명화, B1 자연어 규칙, B2 브리핑, B4 리스크 가드, B6 에이전트 챗, B7 적립식 | 데모 시나리오·소개서 슬라이드에서 하이라이트 |

## P1 — 웹 서비스화 뼈대와 함께 (새 대화 첫 작업)

- **A1 대시보드**: FastAPI 백엔드 + SSE(실시간 이벤트). 무디자인 카드 구성 — 시세, 포지션·평단, 예산 게이지(AP2), 에이전트 협상 로그, 최근 거래 목록(A5의 화면), AI 판단 피드(A6). 디자인 시안 수령 시 스킨만 교체 가능한 구조(템플릿/CSS 분리).
- **A2 긴급정지**: 서버에 trading_enabled 플래그. 빨간 버튼 → 신규 판단·결제 즉시 중단(진행 중인 정산 1건은 마무리) → "재개" 버튼. 정지/재개 모두 이벤트 로그 기록. 정지 주체(사람/리스크가드)도 기록.
- **A6 판단 타임라인**: 기존 decision_source/decision_reason 데이터를 시간순 피드로 노출. [gemini]/[rule-fallback] 배지 표시.
- **A7 손익 리포트(라이트)**: 실현손익·수익률·평균단가 카드. (상세 리포트는 P2)
- **A5 거래 내역(화면)**: 테이블 + explorer 링크. CSV 내보내기는 P2.

## P2 — 엔진 확장 (P1 완료 직후)

- **A8 수수료 투명화**: broker에 fee_bps(기본 30 = 0.3%) 도입. 견적에 [단가 × 수량 + 수수료 = 총액] 분리 표기. AP2 한도 검사는 수수료 포함 총액 기준. Gemini 프롬프트에 "수수료 포함 실효 가격" 제공. 영수증·아카이브에 수수료 필드 추가. → 소개서 수익모델(브로커 수수료) 증명 장치.
- **A3 한도 설정 화면**: 예산/건별 한도/허용 종목 폼 → 새 mandate 생성·서명 → 적용. 변경 시 일시정지 상태에서만 적용(레이스 방지). 변경 이력 로그.
- **A4 거래 알림**: 1차 = 브라우저 알림(SSE 토스트 + Web Notification). 체결·거부·정지 이벤트. (텔레그램 봇은 P3 옵션)
- **B7 적립식(DCA) 모드**: 전략 타입 선택 — 조건형(현행) / 적립형(주기마다 정액 매수). 적립형도 mandate 한도 동일 적용. 증권사 표준 기능 대응.
- **B2 데일리 브리핑**: "오늘 요약" 버튼(+ 하루 1회 자동): 거래·판단 로그를 Gemini가 한국어 리포트로 → 대시보드 카드 + 아카이브 저장.

## P3 — 대화형·감시 (배포 전후, Gemini 통합 확장)

- **B1 자연어 규칙 설정**: 입력창에 "178 밑이면 30달러씩 사줘" → Gemini가 규칙 JSON(buy_below/sell_above/spend/symbols/budget)으로 변환 → **변환 결과를 사용자 확인 화면에서 보여주고 승인 시에만 서명·적용**(프롬프트 인젝션·오해석 방지). 모호하면 되물음. 데모 오프닝 장면.
- **B6 에이전트 챗**: 대시보드 채팅. 현재 상태(포지션·예산·최근 판단·시세)를 컨텍스트로 Gemini가 답변("지금 왜 안 사?"). **행동 변경 요청은 챗이 직접 실행하지 않는다** — "규칙 변경 제안 카드"를 생성해 A3/B1 승인 플로우로 연결(납득 → 유지, 다른 생각 → 규칙 변경 제안). mandate 우회 불가 원칙의 UI 구현.
- **B4 리스크 가드**: 감시 루프 — 직전 N틱 대비 변동률 ±X% 초과 시 발동. 동작 모드 토글: "알림만" / "알림 + 자동 일시정지"(기본값 — 안전 우선, 사용자 변경 가능). 자동 정지 시 재개는 사람만 가능(A2 재사용). 발동 이력 타임라인 표기. → 사용자 고민(정지 vs 알림)을 두 모드 지원으로 해소.

## 데모 서사 연결 (소개서·영상용 메모)

1. B1로 시작: 사람이 말로 규칙을 정함 → 서명
2. 에이전트들이 A2A 협상·Gemini 판단·온체인 정산 (A1·A6에서 실시간 관찰)
3. B4 발동 or 거부 케이스: "한도 밖·위험 상황은 기계적으로 차단" (가드레일 어필)
4. B2 브리핑: "오늘 +7 USDC" — A7·A8과 함께 상업성(수수료 수익모델) 마무리

## 미결정·확인 필요

- B4 발동 임계값(기본 제안: 3틱 내 ±5%)과 기본 모드(제안: 알림+자동 정지)
- ~~A8 수수료율 기본값~~ → **0.3%(30bps) 확정 (2026-07-23, 사용자)**. 단, **0.1%(10bps) 인하안은 최종 제출 전 재검토** — 0.3%는 업계 표준이라 무난하지만 어필 포인트가 안 되고, 0.1%는 "저수수료" 차별화 포인트가 될 수 있음. `.env BROKER_FEE_BPS` 로 변경 가능. **제출물(소개서 수익모델 수치) 확정 시 Claude가 사용자에게 다시 물어볼 것.**
- A4 텔레그램 확장 여부(P3 옵션)

## P2 구현 중 확정된 세부 사항 (2026-07-23, 사용자)

- A8 수수료: **양방향** — 매수 `총액 = 소계 + 수수료`, 매도 `수령액 = 소계 − 수수료`. 매수 견적은 수수료 포함 총액이 요청 금액(spend)을 넘지 않게 수량을 내림 계산. 평단은 수수료 포함 실효 단가 → 실현손익 = 수수료 차감 후 순손익.
- B7 DCA 주기: **틱 단위** ("N틱마다", 기본 5틱 ≈ 40초).
- B2 자동 생성: **장 마감 시각(DAILY_BRIEFING_TIME, 기본 16:00 로컬, 하루 1회) + 세션 종료 시 자동 + 수동 버튼** 3경로.
