# SynapStock 랜딩 워딩

시안 그대로 다섯 칸 + 맨 아래 한 줄입니다. 회색 배경으로 감싼 게 화면에 그대로 들어가는 글자예요.

브랜드는 `SynapStock` 입니다. 시안엔 `402 Guard` 로 되어 있는데, 그건 제품 안에 있는 기능
이름이에요. 본문 문장 안에 나오는 402 Guard 는 전부 맞으니까 그대로 두시면 됩니다.

영문 제목은 큰 제목 위에 작은 글씨로 얹는 식으로 가시면 좋을 것 같아요. 본문이 다 한국어라
영문만 크면 톤이 갈립니다.

---

## 1. 맨 위 바

`SynapStock` ｜ `소개` · `대시보드` · `디스커버리` ｜ 버튼 `지갑 연결하고 시작하기`

---

## 2. 첫 화면

**큰 제목** — 줄바꿈 고정
```
손을 떼려면,
누군가는 청구서를 읽어야 합니다.
```

**그 아래 설명**
```
AI 에이전트가 사용자가 정한 한도 안에서 스스로 사고팔고 USDC 로 정산합니다.
402 Guard 가 서명 직전에 청구서를 대조해서, 사람이 화면을 지켜보지 않아도 됩니다.
```

**버튼 2개** `지갑 연결하고 시작하기` · `데모 대시보드 보기`

**버튼 바로 밑 한 줄**
```
감시 없는 자율. 건건이 승인하지 않는 결제.
```

**그 밑에 작은 글씨로 쓰는 기술 이름**
```
A2A · AP2 · x402 on Solana · 지갑으로 로그인합니다(비밀번호 없음)
```

### 근거 3줄

첫 화면 안에 같이 있어야 합니다. 큰 제목이 한 주장의 근거라서, 떨어뜨려 놓으면 그냥 문구
셋이 됩니다. 버튼 아래나 첫 화면 맨 밑에 가로로 놓으면 될 것 같아요.

| 큰 글자 | 아래 설명 |
|---|---|
| `서명 전에 멈춥니다` | `어긋나면 서명이 만들어지지 않습니다` |
| `예산을 코드가 집행합니다` | `위임장에서 실제로 차감됩니다` |
| `사는 쪽도 파는 쪽도 봅니다` | `자산이 나갈 때도 대조합니다` |

### 오른쪽 화면 예시

시안 그대로 가면 됩니다. 가드 로그 세 줄만 이걸로 바꿔 주세요.
```
차단　GUARD_PAYEE_UNKNOWN — 수취인이 합의한 상대가 아님
차단　GUARD_SEMANTIC_MISMATCH — 금액은 맞는데 청구서 설명이 주문과 다름
서명　STOCK:tAAPL — 수취인 · 금액 · 자산 · 설명 일치
```

지표 네 칸 이름은 `지출 시도` · `가드 차단` · `한도 거부` · `유출`. 숫자는 흐리게 처리할 거라
이름만 맞으면 됩니다.

그림 밑에 붙는 이름은 `대시보드 화면 예시` 로 해 주세요. **`실시간`·`라이브` 는 쓰면 안 됩니다** —
손으로 만든 그림인데 실시간이라고 적었다가 들키면 진짜 거래 기록까지 의심받습니다.

## 3. 두 번째 칸 — 문제

이 페이지의 심장입니다. 여기서 "어?" 가 안 나오면 뒤가 다 "있으면 좋은 기능"으로 읽혀요.

**위에 작은 영문** `Nobody Reads the Invoice`

시안의 `The Problem — AI agents either can't act, or require full key access` 는 안 씁니다.
우리 문제는 "행동을 못 한다"가 아니라 "청구서를 아무도 안 읽는다" 예요.

**큰 제목** — 줄바꿈 고정
```
AI 에게 지갑을 맡기면 알아서 사고팝니다.
그런데 AI 는 가짜 영수증을 의심할 줄 모릅니다.
```

**카드 3개** (세미콜론이 작은 글씨 ; 제목 ; 본문 나눠 주는 겁니다)
```
x402 ; 키는 지키지만, 내용은 안 본다 ; 구매자의 키는 지킵니다. 그런데 구매자가 무엇에
서명하는지는 아무도 검증하지 않습니다.

AP2 ; 집행할 사람이 이 세계엔 없다 ; 수취인 제약은 규격에 정의돼 있습니다. 그런데 자기
지갑으로 결제하는 세계에는 그걸 집행할 주체가 없습니다.

결과 ; 한 번의 서명 = 즉시 손실 ; 사람이 빠진 결제에서 잘못된 서명은 되돌릴 수 없습니다.
```

**카드 밑에 강조 칸 하나 더** — 이 페이지에서 제일 강한 문장입니다.
```
한도는 지켜졌습니다. 그리고 전액을 잃습니다.

악성 판매 에이전트는 한도를 넘지 않습니다. 금액을 건별 한도 바로 아래로 맞추고,
수취인 주소 하나만 자기 지갑으로 바꾸면 됩니다.
```

제목의 마침표를 쉼표로 바꾸지 마세요. 끊어 읽어야 반전이 삽니다.

## 4. 세 번째 칸 — 해결

여기 들어가는 건 x402·AP2 카드가 아니라 아래 ①②③ 입니다.
시안 세 칸(`예산 설정` / `AI 정책` / `트랜잭션 승인`)이 순서까지 딱 이 자리예요.

**위에 작은 영문** `The Gate Before the Signature`

**큰 제목**
```
사람이 정하고, 코드가 지킵니다
```

**그 아래 설명**
```
AI 에이전트가 사람 없이 결제할 수 있도록, 서명 직전에 청구서를 대조하는 승인 게이트입니다.
```

**카드 3개**
```
① 한도 ; 한도를 한 번 서명합니다 ; 총예산·건별 최대·허용 종목을 한 번 서명하면,
그 뒤로는 다시 묻지 않습니다.

② 집행 ; 예산을 코드가 집행합니다 ; 표시용 숫자가 아니라 위임장에서 실제로 차감됩니다.
넘는 청구는 서명되지 않습니다.

③ 대조 ; 합의한 그 청구서일 때만 서명합니다 ; 수취인·금액·자산·종목에 청구서 설명까지
맞춰 보고, 하나라도 어긋나면 서명 자체가 만들어지지 않습니다.
```

가운데 카드 `AI 정책` 은 **`② 집행`** 으로 바꿉니다. "AI 가 정책을 정한다"로 읽히는데
우리는 정반대예요 — 정책은 사람이 정하고 AI 는 그걸 못 넘습니다.

①②③ 은 시간 순서라 순서 고정입니다.

## 5. 네 번째 칸 — 도는 순서

시안 다섯 칸 그대로인데 이름이 다 바뀝니다. 특히 4번 `승인` → `대조` 요.
`승인` 이 있으면 사람이 매번 승인하는 걸로 읽히는데, 이 제품 핵심은 "사람을 다시 안 부른다" 입니다.

**위에 작은 영문** `How a Payment Runs`

**큰 제목**
```
한 번 서명하면, 나머지는 에이전트와 게이트가 합니다
```

| | 이름 | 영문 | 누가 | 한 줄 |
|---|---|---|---|---|
| 1 | `한도 서명` | Sign Limits | `사람` | `예산과 한도를 한 번 서명합니다` |
| 2 | `판단` | Decide | `AI` | `시세를 보고 살지, 팔지, 기다릴지 정합니다` |
| 3 | `협의` | Negotiate | `에이전트끼리` | `견적을 합의하고 청구서를 받습니다` |
| 4 | `대조` | Verify | `402 Guard` | `청구서를 위임장·견적과 맞춰 봅니다` |
| 5 | `정산` | Settle | `블록체인` | `Solana 에서 USDC 로 결제하고 도착까지 확인합니다` |

1번만 사람이 하고 2~5 는 사람이 없습니다. 이 대비가 보이면 좋아요 —
1번만 색이 다르거나, 2~5 를 한 묶음으로 감싸거나.

`누가` 칸은 살려 주세요. 누가 무슨 일을 하는지가 한눈에 들어옵니다.

## 6. 다섯 번째 칸 — 누가 쓰나

**위에 작은 영문** `Who it's for`

**큰 제목**
```
에이전트에 지갑을 붙이려는 순간, 모두가 같은 문제를 만납니다
```

**카드 2개**
```
개발자 ; 에이전트에 결제를 붙이는 팀 ; 결제는 x402 로 쉽게 붙습니다. 그런데 "이 청구서를
믿어도 되는가" 는 각자 알아서 짜야 합니다.

파워 유저 ; 자율 매매 도구를 쓰는 사람 ; 반복되는 결제라 위험이 쌓이는 최악의 조건.
여기서 되면 다른 곳에서도 됩니다.
```

**옆에 버튼 칸** (시안처럼 카드 옆에 나란히)
```
지갑을 연결하면 바로 시작합니다

비밀번호를 만들지 않습니다. Solana 지갑이 1회용 메시지에 서명하면 그게 로그인이고,
자금은 움직이지 않습니다.
```
버튼 `지갑 연결하고 시작하기` · `데모 대시보드 보기`

`자금은 움직이지 않습니다` 는 빼지 마세요. "지갑 연결" 하면 다들 송금부터 떠올리는데
여기 서명은 소유 증명일 뿐이에요.

두 번째 버튼(`데모 대시보드 보기`)은 지갑 없는 심사위원용 경로라 꼭 필요합니다.

## 7. 페이지 맨 아래

시안엔 없는데 하나 필요합니다. `블록체인에서 직접 확인하기` 를 제일 눈에 띄게 해 주세요 —
"화면 말고 진짜 거래를 보여 달라"가 이 대회 심사 기준이라 여기가 제일 무거운 증거입니다.

**작은 제목**
```
직접 확인하십시오
```
**링크 4개**
```
블록체인에서 직접 확인하기 · x402 디스커버리 · 대시보드 · GitHub 저장소
```
**한 줄**
```
402 Guard · A2A · AP2 · x402 on Solana
```
**작은 글씨 안내**
```
결제 통화는 Circle 이 발행한 공식 devnet USDC 입니다(발행 권한은 저희 것이 아닙니다).
사는 대상인 주식 토큰만 자체 발행입니다. 데모는 테스트 네트워크에서 동작하고 실제
증권거래·실제 자금 이동은 없으며, 투자 조언이 아닙니다.
```

이 안내는 법적 문구라 문장 줄이지 마세요.

## 몇 가지만

- 그대로 두는 이름 — `SynapStock` `402 Guard` `A2A` `AP2` `x402` `USDC` `Solana` `devnet` `tAAPL`
- `GUARD_PAYEE_UNKNOWN` `GUARD_SEMANTIC_MISMATCH` 도 원문 그대로. 한글로 풀면 코드에서
  나온 값이라는 인상이 사라집니다.
- 한국어 줄바꿈이 어절 중간에서 안 끊기게 해 주세요. 기본값이면 "지출을," 이
  "지출" + "을," 로 잘립니다.
- 오른쪽 위로 올라가는 그래프·초록 화살표·수익률 강조는 피해 주세요. 우리가 파는 건
  수익률이 아니라 지출 통제라서, 그림 하나로 트레이딩 봇처럼 읽힙니다.
