### 1) 문제 정의 (Problem Statement)

**AI 에이전트에게 지갑을 맡기면 사람 없이도 알아서 사고팝니다. 그런데 AI 는 가짜 영수증을
의심할 줄 모릅니다.**

사람이 결제 버튼을 누르는 시대에는, 청구서가 이상하면 사람이 눈치챘습니다. 에이전트가
대신 결제하면 그 마지막 확인이 사라집니다. 그리고 지금 표준 스택에는 그 자리를 메우는
주체가 없습니다:

- **x402** 는 구매자의 **키**를 지킵니다(로컬 서명·판매자가 키를 갖지 않음). 하지만 구매자가
  **무엇에 서명하는지**는 검증하지 않습니다 — 수취인이 합의한 상대인지, 청구액이 합의 견적과
  같은지를 묻는 주체가 스펙에 없습니다. 게다가 `exact` 스킴은 **실행되면 되돌릴 수 없는 push
  결제**입니다.
- **AP2** 는 수취인 제약(`allowed payees`)을 **정의하고**, 그 집행을 Credential Provider ·
  Network · Merchant Payment Processor 에 배정합니다. 그런데 **self-custody 온체인 플로우에는
  그 세 주체가 존재하지 않습니다.** 집행 지점이 공석이 됩니다.

**실제 위협 — 우리 저장소에서 직접 재현한 것들**(`scripts/red_team.py`, 실제 결제 경로를
그대로 태움):

1. 악성 브로커가 **건별 한도 안쪽 금액**(45 한도에 44.94)으로 정상처럼 청구하되 **수취인만
   자기 지갑으로** 바꾼다 → mandate 한도도, x402 스펙도, 세션키 스코프도 이걸 막지 않는다.
   *"한도를 지켰는데 전액을 잃는다."*
2. 청구서와 견적이 서로 **자기정합**인데 사용자가 의도한 지출(30)보다 크다 → 둘의 정합만
   보는 방어는 못 잡는다.
3. 매도 레그에서 지불 자산을 주식 → **USDC** 로, 수량을 예산 밖 **유휴 잔액 전액**으로 바꾼다
   → '나가는 돈'만 보는 방어는 이 방향을 안 본다.
4. 금액·수취인·자산·종목이 **전부 정상**인데 사람이 읽는 설명만 다른 물건을 가리킨다
   ("본 청구는 12개월 자동 결제 구독의 첫 회차입니다") → **하드 검사 전부 통과.**

**왜 중요한가(가설).** 에이전틱 커머스가 퍼지면 사람이 매 결제를 확인하지 않습니다. 승인
게이트가 없으면 **한 번의 잘못된 서명 = 즉시 온체인 자금 손실**이고, 자율 매매처럼 반복·고빈도
결제에서는 손실이 누적됩니다. 그리고 이 위험은 우리가 지어낸 것이 아닙니다 — 결제 레일 중
하나인 pay.sh 의 구독 문서가 스스로 경고합니다: **활성 구독이 지갑을 조용히 소진시킬 수 있으니
정기적으로 감사하라, 그리고 구독 활성화는 사용자 명령이 아니라 유료 요청의 부수효과로 자동
발생한다.**

> **한 문장**: 자율 결제를 가능하게 하려면, 사람 대신 청구서를 읽는 계층이 있어야 합니다.

### 2) 솔루션 요약 (Solution Overview)

**402 Guard 는 AI 에이전트가 서명하기 직전, 이 청구서가 합의한 그 청구서인지 대조합니다.
그래서 사람이 화면을 지켜보지 않아도 됩니다.**

**에이전트가 자율 판단하는 것**: Gemini(무료 티어)가 시세·지표(MA5/MA20·등락률·변동성·평단
손익률·직전 행동 회고, 옵션으로 TA 패턴)를 보고 **매수/매도/보류**를 판단합니다.
**단, AI 재량은 '멈추는 방향'으로만 열려 있습니다** — 규칙 신호 없는 개시는 프롬프트가 아니라
**코드**가 막습니다(`_rule_gate`).

**에이전트가 실행하는 온체인 트랜잭션**: Solana 에서 **USDC ⇄ 토큰화 주식 토큰**을 양방향
정산합니다. 매수는 USDC 를 보내고 주식을 받고, 매도는 주식을 보내고 USDC 를 받습니다.
각 결제는 A2A 3단계(`payment-required` → `payment-submitted` → `payment-completed`)를 지나며,
온체인 Memo(`AT1:{order_id}:{mandateSig8}`)로 주문과 트랜잭션이 묶입니다.

**402 Guard 가 서명 직전에 하는 일**:

| 계층 | 검사 | 성격 |
|---|---|---|
| 하드 검사 **8종** | 주문번호 형식 · 결제 자산 · 종목(허용 목록 **및** 지금 주문한 그 종목) · 수취인 allowlist · **단위**(청구서의 decimals) · 금액(합의 견적과 base units 오차 0) · **의도 지출 상한** · 건별 한도 | 결정론 |
| 의미 대조 **1종** | 청구서의 사람이 읽는 설명이 우리 주문 의도와 **같은 물건**인가 | LLM — **차단만 가능** |
| 매도 대칭 | 자산을 내보내는 방향에서도 자산·수취인·수량·종목 대조 | 결정론 |
| 정산 후 | 온체인 잔액 재조회로 실제 도착 확인 | 탐지 + 세션 정지 |

**위반이면 서명 자체가 만들어지지 않습니다.** 이 계층의 유출이 0 인 것은 측정 결과가 아니라
구조적 사실입니다.

**AI 를 어디에 두었는가(축②)**: 두 레이어 모두 **AI 에게 거부권만 주고 통과 권한은 주지
않습니다.** ①판단 레이어의 규칙 게이트와 ②청구서 레이어의 의미 대조가 같은 권한 구조입니다.
오탐이면 거래 한 건을 안 하고, 미탐이면 하드 검사 8종이 그대로 남습니다 — **위험이
비대칭입니다.** 실측 근거: TSLA 481봉 세션에서 Gemini 가 *"MA5 대비 3% 이상 낮아 조건 충족"*
이라고 **사실과 다르게 단언하며** 매수를 시도한 2건을 코드가 차단했습니다(그 세션의 90.2%가
순수 Gemini 판단). 상세 [`docs/axis2_ai_narrative.md`](axis2_ai_narrative.md).

**키 분리**: 위임자(사용자) 키와 실행자(에이전트) 키가 분리돼 있어 "위임" 서사가 코드에서도
참입니다. 사용자는 **지갑으로 로그인**합니다 — 비밀번호를 만들지 않습니다.

**증빙**: 첫 화면 KPI 는 수익률이 아니라 **지출 시도 · 가드 차단 · 한도 거부 · 유출 0.00 USDC**
입니다. `scripts/red_team.py` 가 공격 7종 차단 매트릭스와 정상 거래 14건 오탐을 **같은 실행
안에서** 산출하고, 계층을 합치지 않습니다(서명 전 차단 / 판매자측 방어 / 정산 후 탐지를 나눠
셈). 트랜잭션 해시·판단 출처 집계가 `artifacts/tx/` 에 아카이빙됩니다.

### 2-1) 정직한 경계선 (소개서·발표에 그대로 포함)

- 막는 것은 **위조**이지 **신뢰 실패**가 아닙니다 — allowlist 안의 상대가 배신하면 못 막습니다.

  ⚠ 다만 **2026-07-24 아카이브(`8L9feSS…`)는 발행 권한이 구매자 지갑 자신**이었습니다 —

### 3) 당위성 (킥오프 3세션 근거 — 소개서·발표에 그대로 인용)
- **왜 온체인·왜 자율인가:** 킥오프에서 유준혁·김채린 모두 "마이크로페이먼트"는 약한 논거라
  못박았다(카드도 배치정산 가능). 진짜 해자는 **인증 없는 결제·저수수료·속도**이고 경쟁군은
  카드 네트워크다. 그런데 인증 없는 결제 = **사람이 매 건 승인하지 않는 결제**이고, 사람이
  빠지면 **한 번의 잘못된 서명 = 즉시 온체인 자금 손실**이 된다. → **인증 없는 자율 결제를
  가능케 하려면 사람 대신 청구서를 검증하는 계층이 필수**이고, 402 Guard 가 그 계층이다.
- **레이어 정합:** 유준혁 세션이 해커톤에 추천한 3개 타깃 레이어(커머스·체크아웃 / 신원·의도
  증명 / **검증·가드레일**) 중 **검증·가드레일**을 정면으로 구현한다. "AI 트레이딩 봇"은 어느
  레이어도 아니지만 402 Guard 는 발표자가 지목한 자리에 앉는다.
- **자율성 축 우위:** Google Cloud 데모조차 "사람이 승인하면 버튼 클릭과 다를 게 없다"고
  자평했다. 우리는 **사람이 미리 서명한 정책(mandate)을 코드가 매 건 강제**해, 사람을 부르지
  않고도 안전한 자율 결제를 만든다(pay.sh 의 "매 건 생체인증"보다 더 자율적).
- **심사 4축 매핑:** ①혁신성·UX·상업성(검증·가드레일 레이어 신설 + 공격 재현 CLI
  `scripts/red_team.py --attacker` + 수익률 아닌 KPI)
  ②AI 활용도(Gemini 판단은 한도를 못 넘음 — AI가 무엇을 판단하든 게이트가 상수) ③기술·인프라
  (자체 x402+AP2+A2A+USDC+Memo 대사) ④실제 구동(localnet 풀사이클 교차검증 PASS). 상세 근거는
  [`docs/differentiation.md`](differentiation.md) §7.
