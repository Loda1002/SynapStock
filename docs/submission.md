## 2. 프로젝트 소개 (DRAFT — 개발 종료 후 확정)

### 1) 문제 정의 (Problem Statement)
- AI 에이전트가 **사람 없이** 지갑으로 직접 결제하는 시대가 온다. 그런데 x402 결제 스펙은
  구조적으로 **파는 쪽(판매자)** 을 보호하도록 설계돼 있고, **사는 쪽(사람 없이 결제하는 구매
  에이전트)** 을 보호하는 계층이 비어 있다.
- 실제 위협(우리 저장소에서 직접 재현): 악성 브로커가 **한도 안쪽 금액**으로 정상처럼 청구서를
  만들되 **수취인(pay_to)만 자기 지갑으로** 바꾸면, 현재 표준 흐름에선 구매 에이전트가 그대로
  **무검증 서명** → 자금이 엉뚱한 곳으로 나간다. (AP2 `authorize()`가 pay_to 미검사,
  `exact`인데 금액 비교가 `<`, `allowed_asset`이 죽은 필드, Memo·HTTP 402 부재,
  에이전트가 자기 허가서를 자기 키로 서명 등 실제 결함으로 성립.)
- 왜 중요한가(가설): 에이전틱 커머스·자율매매가 퍼지면 사람이 매 결제를 확인하지 않는다.
  승인 게이트가 없으면 **한 번의 잘못된 서명 = 실제 온체인 자금 손실**이고, 반복·고빈도 결제
  (자율 매매)에서 손실이 누적된다. → "사는 쪽 에이전트를 위한 결제 방화벽"이 필요하다.

### 2) 솔루션 요약 (Solution Overview)
- **402 Guard** = 구매 에이전트가 어떤 결제든 **서명하기 직전에 반드시 통과**해야 하는 지출
  승인 게이트.
- 자율 판단(무엇을): Gemini(무료 티어)가 시세·지표(MA5/MA20·추세·평단 손익률·변동성·직전
  행동 회고 + TA)를 보고 **매수/매도/보류**를 판단한다. 단, 사용자가 정한 조건·예산 한도 안에서만.
- 온체인 트랜잭션(무엇을 실행): Solana에서 **USDC ⇄ 토큰화 주식 토큰**을 양방향 정산(자체 x402).
  AP2 mandate로 **순투입 한도를 온체인적으로 강제**하고, 매도 대금은 한도로 환입(release)한다.
- Guard 핵심 동작:
  - `check_demand`: 청구서 **4항목**(수취인 pay_to / 자산 allowed_asset / 금액 exact 정합 /
    Memo 바인딩)을 사용자 mandate와 대조 → 하나라도 어긋나면 **서명 거부, 유출 0**.
  - `check_delivery`: 결제 후 **온체인 재조회**로 실제 이체가 청구서대로 됐는지 검증.
- 키 분리: **사용자 키(mandate 서명자)** 와 **에이전트 키(실행자)** 를 분리 → "위임" 서사가
  코드에서도 참이 된다.
- 증빙: 첫 화면 KPI = **시도 · 차단 · 유출 0.00 USDC · 오탐 0**. `scripts/red_team.py`가 공격
  3종 차단 매트릭스 + 정상거래 오탐 0을 동시 산출. 트랜잭션 해시·실행 로그 아카이빙(`artifacts/tx/`).

### 3) 당위성 (킥오프 3세션 근거 — 소개서·발표에 그대로 인용)
- **왜 온체인·왜 자율인가:** 킥오프에서 유준혁·김채린 모두 "마이크로페이먼트"는 약한 논거라
  못박았다(카드도 배치정산 가능). 진짜 해자는 **인증 없는 결제·저수수료·속도**이고 경쟁군은
  카드 네트워크다. 그런데 인증 없는 결제 = **사람이 매 건 승인하지 않는 결제**이고, 사람이
  빠지면 **한 번의 잘못된 서명 = 즉시 온체인 자금 손실**이 된다. → **인증 없는 자율 결제를
  가능케 하려면 사람 대신 청구서를 검증하는 계층이 필수**이고, 402 Guard 가 그 계층이다.
- **레이어 정합:** 유준혁 세션이 해커톤에 추천한 3개 타깃 레이어(커머스·체크아웃 / 신원·의도
  증명 / **검증·가드레일**) 중 **검증·가드레일**을 정면으로 구현한다. "AI 트레이딩 봇"은 어느
  레이어도 아니지만 402 Guard 는 발표자가 지목한 자리에 앉는다.
- **자율성 축 우위:** Google Cloud 데모조차 "사람이 승인하면 버튼 클릭과 다를 게 없다"고
  자평했다. 우리는 **사람이 미리 서명한 정책(mandate)을 코드가 매 건 강제**해, 사람을 부르지
  않고도 안전한 자율 결제를 만든다(pay.sh 의 "매 건 생체인증"보다 더 자율적).
- **심사 4축 매핑:** ①혁신성·UX(검증·가드레일 레이어 신설 + 공격 콘솔 + 수익률 아닌 KPI)
  ②AI 활용도(Gemini 판단은 한도를 못 넘음 — AI가 무엇을 판단하든 게이트가 상수) ③기술·인프라
  (자체 x402+AP2+A2A+USDC+Memo 대사) ④실제 구동(localnet 풀사이클 교차검증 PASS). 상세 근거는
  [`docs/differentiation.md`](differentiation.md) §7.
