## 3. The Problem — 이게 왜 필요한가

이 페이지의 심장입니다. 여기서 "어?" 가 안 나오면 뒤가 다 "있으면 좋은 기능"으로 읽혀요.

**영문 라벨** `The Problem`

**제목** — 줄바꿈 고정
```
AI 에게 지갑을 맡기면 알아서 사고팝니다.
그런데 AI 는 가짜 영수증을 의심할 줄 모릅니다.
```

시안의 `AI agents either can't act, or require full key access` 는 안 씁니다.
우리 문제는 "행동을 못 한다"가 아니라 "청구서를 아무도 안 읽는다" 예요.

**따라오는 설명** — 줄바꿈은 공간에 맞춰서
```
사람이 결제하던 시절에는 청구서가 이상하면 사람이 눈치챘습니다. 에이전트가 대신 결제하면
그 마지막 확인이 사라집니다. 그리고 지금 표준 규격에는 그 자리를 메우는 주체가 없습니다.
```

**카드 3개** (세미콜론 = 태그 ; 제목 ; 본문)

```
x402 ; 키는 지키지만, 내용은 안 본다 ; x402 는 구매자의 키를 지킵니다 — 로컬 서명이고
판매자는 키를 갖지 않습니다. 하지만 구매자가 무엇에 서명하는지는 검증하지 않습니다.
수취인이 합의한 상대인지, 청구액이 합의 견적과 같은지를 묻는 주체가 규격에 없습니다.

AP2 ; 집행할 사람이 이 세계엔 없다 ; AP2 는 수취인 제약을 정의합니다. 그리고 그 집행을
자격증명 발급자·결제망·가맹점 결제 처리자에 배정합니다. 그런데 자기 지갑으로 결제하는
세계에는 그 세 주체가 존재하지 않습니다. 집행 지점이 공석이 됩니다.

결과 ; 한 번의 서명 = 즉시 손실 ; 사람이 빠진 결제에서 잘못된 서명은 되돌릴 수 없습니다.
반복되는 결제일수록 손실이 쌓입니다.
```

카드 3장은 분량이 일부러 다릅니다. 앞 둘이 설명이고 마지막이 결론이라 짧게 끝나야 해요.
높이 억지로 맞추지 마세요.

**마무리** — 카드 아래 강조 띠 하나로. 이 페이지에서 제일 강한 문장입니다.

제목
```
한도는 지켜졌습니다. 그리고 전액을 잃습니다.
```
본문
```
악성 판매 에이전트는 한도를 넘지 않습니다. 넘을 이유가 없습니다. 금액을 건별 한도 바로
아래로 맞추고, 종목도 허용 목록 안에 두고, 수취인 주소 하나만 자기 지갑으로 바꾸면 됩니다.
```
판정
```
가드 없는 에이전트의 판정: 한도 안이므로 통과 → 서명. 돈은 나가고 자산은 오지 않습니다.
```

제목의 마침표를 쉼표로 바꾸지 마세요. 끊어 읽어야 반전이 삽니다.

## 4. A safe execution layer — 그래서 이렇게 막는다

**자리 주의** — 여기 들어가는 건 x402·AP2 카드가 아니라 **아래 ①②③** 입니다.
x402·AP2 는 문제라서 위 `The Problem` 으로 갑니다. 시안의 3칸
(`예산 설정` / `AI 정책` / `트랜잭션 승인`)이 ①②③ 자리랑 딱 맞아요.

**영문 라벨** `A safe execution layer`

**제목**
```
한도를 정하면, 에이전트는 그 안에서만 씁니다
```

**설명**
```
AI 에이전트가 사람 없이 결제할 수 있도록, 서명 직전에 청구서를 대조하는 승인 게이트입니다.
```

**카드 3개**

```
① 한도 ; 한도를 한 번 서명합니다 ; 총예산·건별 최대·허용 종목·허용 자산을 AP2 위임장에
한 번 서명합니다. 그 뒤로는 다시 묻지 않습니다.

② 집행 ; 예산을 코드가 집행합니다 ; 표시용 숫자가 아니라 위임장에서 실제로 차감됩니다.
잔여 예산을 넘는 청구는 서명되지 않고, 정산이 실패하면 한도가 원복됩니다.

③ 대조 ; 합의한 그 청구서일 때만 서명합니다 ; 수취인·금액·자산·종목·단위를 최소 단위까지
대조하고, 청구서에 적힌 설명까지 주문 의도와 맞춰 봅니다. 하나라도 어긋나면 서명 자체가
만들어지지 않습니다.
```

시안 가운데 카드가 `AI 정책` 인데 **`② 집행`** 으로 바꿉니다.
"AI 가 정책을 정한다"로 읽히는데 우리는 정반대예요 — 정책은 사람이 정하고 AI 는 그걸 못 넘습니다.

①②③ 은 시간 순서라 순서 고정입니다.

## 5. How 402 Guard works — 어떻게 돌아가나

시안 5칸 그대로인데 **이름이 다 바뀝니다.** 특히 4번 `승인(Approve)` → `대조(Verify)` 요.
`승인` 이 있으면 사람이 매번 승인하는 걸로 읽히는데, 이 제품 핵심은 "사람을 다시 안 부른다" 입니다.

**제목**
```
한 번 서명하면, 나머지는 에이전트와 게이트가 합니다
```

| | 이름 | 영문 | 누가 | 설명 |
|---|---|---|---|---|
| 1 | `한도 서명` | Sign Limits | `사람` | `총예산·건별 한도·허용 종목을 사용자가 한 번 서명합니다` |
| 2 | `판단` | Decide | `AI` | `시세와 지표를 보고 살지, 팔지, 기다릴지 정합니다` |
| 3 | `협의` | Negotiate | `에이전트끼리` | `판매 에이전트와 견적을 합의하고 청구서를 받습니다` |
| 4 | `대조` | Verify | `402 Guard` | `청구서를 위임장·견적과 항목별로 맞춰 봅니다` |
| 5 | `정산` | Settle | `블록체인` | `통과하면 서명해 Solana 에서 USDC 로 정산하고, 도착까지 확인합니다` |

**1번만 사람이 하고 2~5 는 사람이 없습니다.** 이 대비가 보이면 좋아요 —
1번만 색이 다르거나, 2~5 를 한 묶음으로 감싸거나.

`누가` 칸의 꼬리표는 살려 주세요. 누가 무슨 일을 하는지가 한눈에 들어옵니다.

## 넣을 자리 있으면 좋은 것 (시안엔 없음 · 안 넣어도 됨)

넣기로 하면 `How 402 Guard works` 뒤에 넣으면 자연스럽습니다.

**써 보시려면 — 세 단계**
```
1  지갑을 연결합니다 ; Solana 지갑으로 메시지 하나에 서명하면 그게 로그인입니다.
   비밀번호를 만들지 않고, 이때 자금은 움직이지 않습니다.
2  한도를 정합니다 ; 전체 예산, 한 번에 쓸 최대 금액, 사도 되는 종목. 여기까지가 사람이 하는 일입니다.
3  켜 두고 둡니다 ; 그 다음부터는 화면을 보지 않아도 됩니다. 무슨 판단을 했고 무엇이 막혔는지는
   대시보드에 그대로 남고, 언제든 멈출 수 있습니다.
```

**왜 카드가 아니라 블록체인인가**
```
제목  AI 는 증권계좌를 만들 수 없습니다. 하지만 지갑은 만들 수 있습니다.

사람 확인을 부르지 않습니다 ; 카드 결제는 결국 명의자를 확인합니다. 에이전트가 사람을
깨우지 않고 결제하려면 다른 길이 필요합니다.
계좌를 열 필요가 없습니다 ; 에이전트는 금융기관에 계좌를 열 수 없지만, 지갑은 코드로 만들어집니다.
밤에도, 국경 밖에서도 돕니다 ; 영업일도 결제망 마감도 기다리지 않습니다.
무슨 일이 있었는지 남습니다 ; 언제 무엇을 얼마에 샀는지가 블록체인에 남습니다.
저희가 보여드리는 화면을 믿으실 필요가 없습니다.

마무리  그런데 사람이 빠지면, 청구서를 읽던 사람도 같이 빠집니다. 그 자리가 402 Guard 입니다.
```

**AI 를 어디에 두었나**
```
제목  AI 재량은 '멈추는 방향'으로만 열려 있습니다
본문  이 제품에서 AI 에게 준 것은 거부권뿐입니다. 통과시킬 권한은 없습니다.
      판단 쪽에서는 AI 가 사겠다고 해도 규칙 신호가 없으면 코드가 되돌립니다.
      청구서 쪽에서는 숫자가 다 맞는데 설명만 다른 청구서를 AI 가 읽고 막습니다.
      어느 쪽이든 AI 가 "해도 된다"고 말할 수는 없습니다.
```

이 칸에 "AI 가 수익을 올립니다" 나 "AI 가 청구서 진위를 판정합니다" 같은 카피나 아이콘은
붙이지 마세요. 둘 다 우리 주장의 정반대입니다.
