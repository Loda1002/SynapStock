## 1. "적용할 수 있는 실제 주식이 있는가?" (사용자 질문 ③)

**결론: 메인넷에는 있다. devnet 에는 없다. 그래서 지금 설계가 옳다.**

사용자의 "지금 적용할 수 있는 주식이 없다"는 조사는 **절반만 맞다**. 정확히는:

| 항목 | 사실 | 검증 |
|---|---|---|
| Backed/Kraken **xStocks** (AAPLx·TSLAx·NVDAx·SPYx) 메인넷 실재 | 민트 주소 온체인 조회로 확인. AAPLx = `XsbEhLAtcf6HdfpFZ5xEMdqW8nfAvcsP5bdudRLJzJp` (Token-2022, decimals 8) | 적대적 검증 통과 |
| **devnet 에는 없음** | 같은 민트를 devnet RPC 로 조회 → `null`. 공식 테스트넷 발행 없음 | **CONFIRMED**(2인 독립 검증) |
| 2차 시장(DEX)은 온체인상 무허가 전송 가능 | transferHook `programId=null`, `defaultAccountState=initialized` | 조건부 — 아래 주의 |
| 유동성 실재 | Jupiter 견적 실호출: 10 USDC → 0.03102375 AAPLx, priceImpact 0.33%. 같은 시점 Pyth AAPL 321.075 와 **0.4% 이내 일치** | 실측 |
| Ondo Global Markets | 2026-01-21 솔라나 상장, 200종+. 단 1차 시장은 **기관 KYC 전용**, 개인 온보딩 "곧" | CONFIRMED |
| Remora rStocks | 솔라나 네이티브 SPL, 24/7, Jupiter/Raydium 거래. 에이전트 접근성 1순위 | medium |

**⚠ "퍼미션리스"라고 단정하면 안 되는 이유** (적대적 검증에서 교정된 항목):
같은 민트에 **permanentDelegate**(발행사가 임의 지갑의 토큰을 동의 없이 회수·소각 가능),
**freezeAuthority**, **pausableConfig**(전역 전송 정지)가 붙어 있다. 전송 훅도 "없는" 게 아니라
*초기화됐지만 비활성* 상태 — 언제든 켤 수 있게 배선돼 있다. 즉 **사전 허가는 없지만 사후 통제권은
발행사가 전부 보유**한다. 소개서에 "누구나 자유롭게"라고 쓰면 반박당한다.

### 그래서 우리 서사는 이렇게 잡는다

> "자산은 이미 온체인에 실재한다(민트 주소·유동성·오라클 일치까지 확인). 다만 **해커톤 규칙상
> 메인넷을 쓰지 않으므로** 데모는 devnet 자체 발행 토큰으로 한다. 코드에서 바뀌는 것은 **민트 상수와
> 스왑 경로 2곳뿐**이다."

이건 변명이 아니라 **로드맵 신뢰도**가 된다. 근거로 §6의 실현 경로 4줄을 소개서에 넣는다.

### 규제 (반드시 정직하게 선언)

- 토큰화 주식 = **증권**이다(SEC 2026-01-28 3개 부서 공동 성명). "규제 밖 신종 자산" 표현 금지.
- 한국 토큰증권 제도 **시행일 2027-02-04** → "지금 상용"이 아니라 **"제도 시행 전에 필요한 인프라를
  먼저 만든다"**는 타임라인 논거로 쓰면 오히려 강점.
- 타인 자산을 위임받아 자동매매하면 **무등록 투자일임업** 리스크(자기자본 15억 요건). 반드시
  *"사용자 자신의 지갑 + 사용자가 서명한 한도 + 언제든 정지"* = **self-custody 도구**로 설명한다.
  화면의 한도·긴급정지·거부 로그가 그 증거물이다.
- 24/7 의 실제 허점: 주식 오라클은 **24/5** 로만 갱신된다. → **stale 가드**(마지막 갱신 N분 초과 시
  자동 보류 + "장 마감" 배지)를 제품 기능으로 노출하면 유일한 허점을 제품이 스스로 방어한다.

## 2. 전략 고도화 (사용자 질문 ②) — "왜 드라마틱하지 않은가"

### 실측 (이 저장소에서 직접 재현, 80봉·예산 100 USDC·규칙 모드)

| 종목 | 전략 | 매수후보유 | **초과수익** | MDD | 시장노출 | 매수/매도 |
|---|---|---|---|---|---|---|
| AAPL | +4.90% | +30.19% | **−25.29%p** | 7.31% | 21% | 4 / 1 |
| TSLA | +11.22% | +2.73% | **+8.49%p** | 8.76% | 65% | 21 / 6 |
| NVDA | +20.15% | +25.82% | **−5.67%p** | 3.38% | 44% | 17 / 6 |

**진단 — 수익이 안 나는 게 아니라 구조가 그렇다:**

1. **벤치마크 열위가 진짜 문제다.** "드라마틱하지 않다"보다 심각한 건 AAPL 에서 *그냥 사서 들고 있는
   것보다 25%p 못하다*는 점이다. 심사위원의 첫 질문이 정확히 이것이고, 지금까지 이 숫자가 어느 문서에도
   없었다(= 먼저 물어보게 된다). 이번에 백테스트에 상시 표기하도록 넣었다.
2. **자본 유휴 79%** (AAPL). 진입 조건이 `MA5 −2%` 단일 트리거라 상승 추세에서는 아예 발동하지 않는다.
3. **3% 고정 익절이 추세를 자른다.** AAPL 은 07-02 익절 후 만기까지 재진입 신호가 0건 — 20봉을 현금으로 보냈다.
4. **손절이 코드에 아예 없다**(`stop_loss` grep 0건). 그래서 모든 백테스트 승률이 100% 로 나온다 —
   이긴 거래만 실현되고 진 건 포지션에 잠기기 때문이다. **승률 100% 는 자랑이 아니라 의심을 부른다.**
5. **Gemini 가 결과를 못 바꾼다.** 규칙 신호가 있어야만 매수/매도가 개시되고 Gemini 는 그 위에서
   *보류만* 가능한 구조(`trading_agent.py`). 즉 설계상 **수익을 만들 수 없고 줄이기만 한다.**
   심사 2축(AI 활용도)의 정량 근거가 현재 0이라는 뜻이기도 하다.

### 처방 (우선순위 = 심사 임팩트 / 시간)

| # | 조치 | 효과 | 시간 |
|---|---|---|---|
| S1 | **데모·대표 지표를 TSLA 로 교체** | 유일하게 벤치마크를 이기는 종목(+8.49%p). 거래 21건이라 화면에 사건이 계속 일어나 "드라마틱"해진다 | 0.5h(완료분 재사용) |

## 3. 웹 페이지 추가 (사용자 질문 ①)

현재 `/` 하나뿐이고, **이미 만들어 둔 `/api/history` 4종을 쓰는 화면이 0개**다(grep 0건).

**구현 방식(코드 근거 있는 결정)**: 해시 라우팅 금지. `app.js` 는 82개 DOM 노드를 null 체크 없이 잡고
즉시 실행하므로 대시보드 카드가 없는 문서에서 로드하면 스크립트 전체가 죽는다. 또 `applyLayout` 이
`[data-card]` 를 localStorage 에 저장하므로 다른 뷰를 같은 문서에 얹으면 배치값이 오염된다.
→ **FastAPI 라우트 + 페이지별 정적 HTML + 페이지별 JS**. 새 페이지는 `data-card` 를 쓰지 않고,
색·간격은 `var(--*)` 만 사용해 7/28 시안 도착 시 스킨 교체 창구(theme.css / DEFAULT_LAYOUT)를 보존한다.

## 7. ⚠ 미검증 — 확인 전까지 사실로 쓰지 말 것

1. **[최우선] 대회 공식 심사 기준·제출물 규격 원문.** 공식 사이트가 JS 렌더링이라 조사 에이전트가
   본문을 못 읽었다. 우리가 아는 "심사 4축·제출물 3종·8/3 마감"은 **킥오프 세션 메모가 유일한 근거**다.
   → **사용자가 브라우저로 공식 사이트·디스코드 공지를 직접 열어 캡처해야 한다.**
2. **[중대] 대회 공식 과제가 "에이전트가 x402 로 클라우드 API 를 결제"이고 지정 인프라가 pay.sh 라는 보도.**
   사실이라면 우리는 결제 *대상*이 다르다(자산 vs API). 이 주장은 **적대적 검증이 세션 한도로 실행되지
   못했다.** CLAUDE.md 제약 6("자체 x402 허용")과 충돌하므로 **1번과 함께 원문 확인 필수.**
   - 사실로 확인될 경우의 최단 대응: pay.sh 문서의 대표 예제가 하필 **주식 시세 API**(`/mpp/quote/AAPL`)라,
     시세 피드를 pay.sh 유료 호출로 바꾸면 *"API 를 결제하고 → 그 판단으로 자산을 결제한다"* 2단 서사가 된다(≈1일).
3. 우리 `x402_solana.py` 는 공식 SVM `exact` 스펙과 **최소 8곳 불일치**(HTTP 402 레이어 없음, 필드명
   `serializedTransaction`, feePayer 미분리, Memo 논스 없음, 금액 `>=` 비교 등). 스펙 문서 자체는 확인됐다.
   → 최소 대응은 README 에 **스펙 대응표 + 미구현 이유**를 먼저 자백하는 것(반나절). 금액 정확 일치와
   Memo 논스는 실제 보안 결함이므로 고치는 편이 낫다.
4. Pyth Hermes 가 **2026-08-18 부터 API 키 의무화** — 제출(8/3)엔 무영향이나 **데모데이(8/21) 이후**다.
   Pyth 를 쓰면 키 발급 + 실패 시 Replay 폴백 필수.
5. 백테스트 표본은 3종목×80봉이다. 통계적 유의성 없음 — 반드시 각주로 명시.
