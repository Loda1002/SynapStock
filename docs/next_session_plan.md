## P1. 계측에서 드러난 잔여 (사용자 항목 ④)

### P1-1. 라이브 URL 에서 심사위원이 아무것도 못 한다 — `UX-02`/`GAP-01`/`CODE-04`

랜딩의 주 CTA 두 곳이 "지갑 연결하고 시작하기"인데, 지갑을 연결해도 시작 버튼이 **401 alert** 다
(`web/server.py:36` `require_control` 이 헤더 토큰만 보고 세션 쿠키를 안 본다). 심사위원이
마지막으로 보는 것이 스타일 없는 브라우저 alert 다.

**채택안(0.3h, 코드 0줄)**: 제출 폼의 라이브 URL 을
`…/app#token=<CONTROL_TOKEN 값>` 으로 낸다. `app.js:942-948` 이 해시를 localStorage 로 옮기고
주소창에서 지운다. README·공개 저장소·영상에는 **토큰 없는 URL 만** 쓴다.

**⚠ 채택 금지**: `require_control` 에서 dry start 를 무인증 허용하는 안. `/api/engine/stop` 은
여전히 토큰 게이트라 외부인이 세션 하나만 켜 두면 심사위원은 "이미 실행 중"으로 막히고 **아무도
못 푼다**. `require_control` 이 도입된 이유 그 자체를 되돌리는 안이다.

**함께**: 랜딩 히어로 하단 한 줄 — "이 데모는 단일 공용 인스턴스입니다 — 조작은 심사용
링크에서만 가능하고, 방문자는 관전(GET·SSE)이 열려 있습니다." (`OPS-09` 를 숨기지 않고 규정)

**촬영 규칙**: 촬영 브라우저에 토큰을 미리 심어 두고 본 촬영은 순수 URL 로만 연다. 편집 시
주소창 프레임 전수 확인. 심사 종료 후 `CONTROL_TOKEN` 1회 로테이션(`OPS-08`).

### P1-2. ★ 쿼터 보류가 '가드 차단' KPI 에 공격 차단과 같은 칸으로 합산된다 — `CODE-03`

첫 화면 대표 지표가 **정직하지 않다.** Gemini 쿼터가 소진되면 의미 대조가 `GUARD_LLM_UNVERIFIED`
로 매수를 보류하는데, 그게 `guard_block_count` 에 그대로 더해져 "가드 차단"으로 표시된다.
악성 청구서를 막은 것과 "검사를 못 해서 멈춘 것"은 전혀 다른 사건이다. 이 제품은 계층을 합치지
않는 것이 미덕인데(red_team 이 3계층을 분리 표기한다) 대표 KPI 가 그걸 어긴다.

**최소안(0.7h)**: `web/engine.py` 의 guard 블록에 `blocked_unverified` 를 분리해 방출하고,
`index.html` 가드 카드의 '가드 차단' 라벨 옆에 `· 검사 불가 N` 을 덧붙인다(`data-guard-legs` 와
같은 방식). **⚠ KPI 칸 자체를 늘리면 재촬영 사유가 되므로 칸은 4개를 유지한다.**
현재 전략 기본값이 추세추종(두뇌 없음)이라 실발생 확률은 낮지만, 조건형을 고른 심사위원에겐 그대로 보인다.
