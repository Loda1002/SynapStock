# 사용자 피드백 (2026-07-23, P2 완료 직후) — 다음 대화 작업 목록

> 사용자가 P2 결과물을 보며 정리한 피드백 원문 + Claude의 1차 분석.
> **작업 사이클 규칙에 따라 "오류" 절이 새 기능보다 최우선.** 착수 전 우선순위·범위는 사용자와 확정할 것.

## 오류 (최우선 — 버그 수정 전용 대화에서 처리)

1. **긴급정지 안 눌렀는데 자꾸 긴급정지됨**
   - 유력 원인(재현으로 확정 필요): 긴급정지 상태(`trading_enabled`)가 세션(start~stop) 경계 밖에서도 유지됨. 정지 → 세션 종료 후에도 "🛑 매매 정지됨" 배지가 계속 남고, 다음 접속 때도 보여 "자꾸 정지됨"처럼 인식될 수 있음. A3 한도 변경이 "정지 상태에서만" 가능해서 정지를 눌렀던 것이 남았을 가능성도.
   - 함께 수정: **추가사항 4 (세션 꺼지면 긴급정지 버튼 비활성화)** — 정지 상태·버튼의 세션 경계를 한 번에 정리.
   - 관련: `web/engine.py` (pause/resume/start 리셋), `web/static/js/app.js` (renderState 버튼·배지 조건)

2. **JSONDecodeError: Invalid \uXXXX escape (line 1 column 215)**
   - 현재 상태: Gemini 판단 응답 파싱(`gemini_decider.py`의 `json.loads`) 실패 시 `TradingAgent.decide`의 except가 잡아 **규칙 폴백으로 흡수됨** (타임라인에 "Gemini 호출 실패(JSONDecodeError…) → 규칙 폴백" 표기, 크래시 아님).
   - 남은 개선: 잘못된 이스케이프 응답의 정화 후 재파싱(예: 원문에서 JSON 블록 추출·`\u` 오류 문자 치환) 또는 1회 재요청 — 폴백 빈도 자체를 낮추기.

3. **알림 꺼짐/켜짐 버튼이 안 됨**
   - 코드 경로: 클릭 → `Notification.requestPermission()` → granted면 켜짐. 사용자 환경에서 안 된 원인 후보: ①브라우저가 이전 거부 이력 때문에 권한 팝업을 다시 안 띄움(주소창 사이트 설정에서 차단됨) ②Windows OS 수준 알림 차단 ③alert 안내가 떴지만 해결 방법이 불명확.
   - 개선 방향: 버튼에 권한 상태(denied/미지원) 표기, denied일 때 해제 방법 안내 문구, 클릭 시 무반응처럼 보이지 않게 즉각 피드백. 재현 환경(사용 브라우저) 확인 필요.

4. **"중간에 갑자기 gemini가 아니라 dca가 판단" — dca가 뭔지**
   - **버그 아님, 설명**: `dca`는 이번 P2에서 추가된 **B7 적립식 모드의 판단 출처 배지**. 헤더의 전략 셀렉트를 "적립형(주기 정액 매수)"으로 두고 세션을 시작하면 Gemini 판단 없이 N틱마다 정액 매수하며 배지가 `dca`로 표기됨. 세션 "중간"에 gemini→dca로 바뀌는 것은 구조상 불가능(전략은 세션 시작 시 고정).
   - "중간에 갑자기"로 보인 유력 이유: 새로고침 시 SSE 히스토리 복원으로 **이전 DCA 세션 로그가 현재 피드에 섞여 보임**. → 개선: 타임라인·로그에 세션 경계 구분선 또는 세션 필터 표시.

## 추가사항 (수익 리포트·UI 확장)

1. **주간 수익 / 월별 수익** — 현재 손익은 세션 단위 인메모리라 서버 재시작 시 소멸. 주/월 집계는 **영속 저장(Firestore 또는 로컬 파일 DB)이 선행 필요** → Cloud Run+Firestore 배포 단계와 묶는 것이 자연스러움.
2. **종목별 수익 확인** — "변경사항 2 (멀티 종목)"와 동일 뿌리. 포지션·손익 구조를 심볼 키 기반으로 확장.
3. **보유 주식·지갑 금액·평가손익(미실현) 표기** — 현재도 계산 가능(현재가×보유수량 − 수수료 포함 원가). 실현손익(A7)과 별도 카드로 "평가손익/총자산(USDC 잔액+주식 평가액)" 추가. 라이브 모드에선 온체인 잔액과 교차 표기.
4. **세션 꺼지면 긴급정지 버튼 비활성화** — 오류 1과 묶어 처리.

## 주식 차트 (시세 카드 개편)

1. 캔들차트: 시가·종가·고가·저가 4가지 (현재 MockPriceFeed는 틱당 단일 가격 → **틱 묶음을 캔들로 집계**하거나 피드가 OHLC를 내도록 모델 확장 필요)
2. 양봉(상승)·음봉(하락) 색 구분
3. 이동평균선(예: MA5·MA20)
4. **시세창이 메인이 되도록 카드 크기 확대** — 참고 UX: 토스, 키움증권, 업비트
- 구현 메모: 외부 CDN 금지 원칙 유지 → SVG 캔들차트 직접 구현(현 스파크라인 대체). 디자인 폴리시가 아니라 기능 확장이므로 무디자인 단계에서 진행 가능.

## 매매 기준 (Gemini 판단 고도화 — 설계 논의 필요)

1. 단순 "상승/하락/목표가 달성"이 아니라 **추세선을 통해 스스로 학습해 수익을 낼 수 있는지 확인**
2. 계속된 하락에서 "목표가보다 낮다"는 이유만으로 사거나, 계속된 상승에서 "목표가보다 높다"는 이유만으로 파는 게 손해일 수 있음 → **Gemini가 추세를 보고 매수/매도 시점을 조절하게 하거나, 우리 로직(예: 연속 하락 중 매수 유예, 상승 추세 중 매도 유예)을 추가할 수 있는지 확인**
- 현재 프롬프트는 "사용자 규칙을 엄격히 적용, 규칙 위반 판단 금지"라 Gemini의 재량이 없음. 개선 방향(사용자와 논의): ①규칙은 하드 가드(AP2)로 두고 판단 프롬프트에 "추세 근거로 매수/매도 '보류' 재량 허용" ②이동평균·추세 지표를 프롬프트 입력에 추가 ③재량 범위를 UI에서 토글(엄격 모드/추세 모드). "학습"은 세션 내 컨텍스트(가격 이력 확장·직전 판단 결과 회고) 수준이 현실적 — 모델 파인튜닝은 해커톤 범위 밖.
- 주의: 심사 서사상 "한도는 기계적 차단(AP2), 판단은 AI 재량"의 경계를 명확히 유지할 것.

## 변경사항 (구조 확장)

1. **적립(DCA) 기준을 틱이 아니라 시간/날짜 단위로 사람이 선택** (예: 1시간마다, 매일 09:00) **혹은 에이전트에게 자연어로 설명해 작동** — 시간 기반은 엔진 루프에서 시각 체크로 구현 용이. 자연어 설정은 P3 B1(자연어 규칙)과 통합.
2. **종목별 전면 확장(멀티 종목)**: 어떤 주식을 샀는지 표시 + 타임라인·로그·손익·시세·거래내역·한도를 **주식별로 설정·확인** — 기존 "P3 여유 시" 항목이었으나 사용자 요구로 승격. 영향 범위 큼: mints/피드/전략/포지션/mandate(allowed_symbols 활용)/모든 UI 카드. 단계적으로: ①데이터 모델 심볼 키화 ②UI 종목 셀렉터 ③종목별 한도.
